## 2. The .NET work (`hamdeck-push`, 38 commits, 00:00–11:33)

This ran from midnight to late morning and shipped **0.4.3 through 0.17.1**. It is worth
recording even though the project is being retired, because several of these fixes are
**the reason the C++ port behaves correctly** — they were found here first and ported.

Fixes that carried across to the C++ host:

- **RX audio websocket must send the session cookie** — the audio socket authenticated
  differently from the API, so audio failed while everything else worked.
- **Accept a bare hostname in the host box.** People type `radio`, not `http://radio:5002`.
- **Open the DEFAULT microphone**, and say what is wrong when it fails. Opening "the first
  device in the list" gets you a monitor loopback, which transmits the desktop's own audio.
- **The Linux host never refreshed its frequency cache** — the panel showed a frequency
  that had been stale for hours. This is the bug `WIP.md` §6 calls *the 3.6-hour frequency
  bug*, and it is why the C++ poller **never falls back to a previous value**.
- **The PTT hotkey fired twice per press**, so the toggle cancelled itself.
- **A transmit watchdog on the Linux host.**
- **Let the audio tail play out before dropping PTT** — otherwise the last syllable of every
  over is cut off. Ported and measured on air in C++: 149 ms drained, clean unkey.
- **Mute the receiver while transmitting.**
- **The client was corrupting and dropping transmit audio.**
- **Gate REC on an explicit `file_recording` flag, failing closed** — this is the
  `/api/record/start` lie in CARRYOVER.md §1, worked around on the client side there and
  fixed properly in the C++ recorder today.

Process fixes worth keeping:

- **CI runs the app.** A green build did not prove it could start — 0.12.0 shipped and could
  not launch at all, because `StartupUri`'s setter rejects null. The build was green.
- **CI: drop the paths filter** — it skipped the run that mattered.
- **A parity test, so missing controls fail the build.**
- **Stop shipping one operator's station as the worked example** (11:33) — the same

## 4. The C++ port (`hamdeck-cpp`, 48 commits, 06:09–now)

### 4a. Built from nothing to a working station host
Scaffold at 06:09; running the station at 11:12. Along the way: civetweb (HTTP and
WebSocket on one port), PBKDF2 session auth compatible with the reference hashes, the
200 ms poller, the serial CAT backend tested through a pty with no radio attached, the
route table, the 18 prefix families, the software VFO lock enforced host-side, `/ws` RX
audio and `/ws/tx` TX audio with permission and single-transmitter gates.

### 4b. Six CAT bugs only the radio could find (§4b in WIP.md)
Recorded here because they are the strongest argument for the hardware window:

- `PR0P2` is **1=OFF / 2=ON**, not a flag.
- **AGC 5 and 6 are also AUTO.**
- **`LK4` is not locked.** Only `LK1` is. A "anything but 0" test reports a lock that
  is not there.
- **Reply slip**: `VS0;ID0682;` — answers can arrive prefixed with the tail of the previous
  one. Fixed by validating the **verb prefix** of every reply.
- **A named device that does not open** was not being probed, so a typo looked like a radio.
- **`alsa_*_device` defaulted to `"default"`** — which is a real device, so a missing
  setting silently captured the wrong thing.

### 4c. TX audio buffering — three attempts, measured each time
Naive write: **290 xruns in 6 s**. Hand-rolled pre-roll: **1512 xruns in 18 s** — worse.
Setting `start_threshold` equal to the feed target: **deadlock**, 923 chunks dropped and
the device stuck in PREPARED forever. What works: threshold at the 80 ms floor, and the
feed stops when the target is *reached*. **5 xruns in 18 s.**

### 4d. Two deployment bugs that made the host lie
- An **unreadable** config was treated as **missing**, so the host silently ran the
  simulator while appearing to be up.
- `DeviceAllow=char-tty` (major 4/136) **blocked USB serial** (major 188) *and* flipped
  systemd into closed device policy.

### 4e. The QML client
Qt Widgets was built, then **deleted** — QML is the client. Live panel, RX and TX audio,
connect screen with no default host, DSP controls, frequency keypad, meters calibrated
from **hamlib tables** rather than invented, the brand palette applied verbatim, admin
page, packaged as a verified Linux `.deb` with Windows and macOS CI.

Bugs fixed along the way: heap corruption on QML exit (`~ApiClient` — now `shutdown()`
wired to `aboutToQuit`), a `Repeater` in a `RowLayout` collapsing to zero width, and a
**console window appearing on Windows launch** (missing `WIN32_EXECUTABLE`).

### 4f. Evening: the audit gap list, worked down
After going through the .NET project **including its front end**, four gaps were found and
all four are now closed:

- **TGXL control** — TCP `C1|autotune`, polled `C1|status`. Called out as a
  *"must must have"*. Done, with the 2 s guard against the tuner reporting `tuning=0`
  before it has started.
- **The WPF panel gaps** — the controls the QML panel did not have.
- **Recording and the replay buffer** — real WAV, verified by reading the files back:
  headers match the bytes on disk, real audio in them, at 22050/mono/16-bit.
- **Session stats** — duration, QSY, TX count, TX time, band/mode maps.

### 4g. Safety work that is not a feature
- **History scrub.** The working tree was clean but the **history** carried site detail.
  Rewritten with `git-filter-repo` using **both** `--replace-text` and `--replace-message`
  — text-only misses commit messages — and verified from a **fresh clone**.
- **`tools/backup.sh`** — bundles, *verifies the bundle*, copies off-box and **compares
  checksums**, because `scp` exiting 0 says the transfer ran, not that the bytes arrived.
  Restore-tested: pulled back, restored, built, tests passed.
- **`tools/deploy.sh`** — new today, and it exists because it went wrong: `sync.sh` builds
  on the VM but installs nothing, so the service spent hours on a binary from 12:18 while
  new routes were "verified" against it. Now the deploy runs the suite, installs, restarts,
  and **compares the build id the running service reports against the binary just
  installed**. Proven by staging a stale binary — the check failed with a mismatch and
  passed on a real deploy.
- Both walk tools **fail closed**: they refuse any target that does not answer
  `{"simulated": true}`, and there is deliberately **no `--force`**.
